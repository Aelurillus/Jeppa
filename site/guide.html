开始使用 / 0.3.0

先在本地跑通，再交给后台。

Python 3.11+，推荐 3.13。机器人不需要 Node.js，也不需要启动浏览器。请先确认自己的账号、目标域及平台条款允许此次接入。

01 / 安装到独立虚拟环境

从 Jeppa 仓库克隆后，在仓库根目录执行。不要假定 PyPI 的同名包属于本项目；发布包请从 GitHub Releases 获取。

Windows PowerShell

git clone https://github.com/Aelurillus/Jeppa.git
cd Jeppa
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install .
.\.venv\Scripts\python.exe -m jeppa --help

不需要激活 venv，也不需要修改 PowerShell 执行策略。下文的所有命令都应使用此虚拟环境的 Python。

Linux / macOS

git clone https://github.com/Aelurillus/Jeppa.git
cd Jeppa
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/python -m jeppa --help

当前 Oopz 适配基于 oopz-sdk==0.16.0 社区 SDK。其 Playwright、Pillow 等传递依赖可能随安装进入环境，但 Jeppa 的文字接入不要求下载 Chromium。

02 / 导入凭据，检查后前台启动

先按本地凭据指南从自己已获授权的账号取得单条请求。只保存到本地 request.local.txt，不要执行所复制的 cURL，也不要发给网站或 issue。

INTERNAL 必须替换成目标域的内部 ID，不是界面展示的域号；多个域重复传入 --area。

.\.venv\Scripts\python.exe -m jeppa.credentials --input request.local.txt --area INTERNAL --output jeppa.local.toml
.\.venv\Scripts\python.exe -m jeppa check-config --config jeppa.local.toml
.\.venv\Scripts\python.exe -m jeppa run --config jeppa.local.toml
.venv/bin/python -m jeppa.credentials --input request.local.txt --area INTERNAL --output jeppa.local.toml
.venv/bin/python -m jeppa check-config --config jeppa.local.toml
.venv/bin/python -m jeppa run --config jeppa.local.toml

check-config 只检查本地格式、必填字段和类型，不登录、不执行插件，也不证明令牌有效或平台在线。run 才会实际连接；首次建议保留前台，发送 /ping 与 /help 核对真实回复，Ctrl+C 清理退出。

默认不会订阅所有域。[bot].areas = [] 仅处理无需域订阅的私信；只填写明确授权的内部域 ID。不要为排障扩大账号或域的访问范围。

03 / default 是完整功能包

省略 [bot].plugins 时自动选择 jeppa.plugins.default:setup。显式指定入口数组后，以数组为准；设为 [] 则不加载任何插件，连 ping/help/status 也不会保留。

[bot]
areas = ["AUTHORIZED_INTERNAL_AREA_ID"]
plugins = ["jeppa.plugins.default:setup"]
default 提供的全部命令
命令行为与边界
/ping文字连通性回复；不是完整平台健康检查。
/help仅显示当前用户、会话有权使用的命令，不消耗所列命令的冷却。
/status运行时长、插件元数据、命令计数及当前机器人连接状态。
/roll 2d6默认 1d6；1–100 颗骰子，每颗 2–1000000 面。
/choose 茶 | 咖啡至少两个非空选项；保留选项本身的内容。
/faq / /faq rules列出或查询本域 FAQ；域间隔离，同域频道共享，私信不可用。
/faq-set rules 请友善交流受限写入，需非空用户白名单；答案最多 1800 字符。
/faq-delete rules受限删除，需非空用户白名单。

FAQ key 是 1–64 个 ASCII 字母、数字、下划线或连字符，以字母或数字开头，不区分大小写。默认插件当前不接受配置项，[plugins.default.config] 必须为空；行为限制不是通过隐藏参数调整。

04 / 权限与插件作用域相交

省略白名单表示不限制，空数组 [] 表示全部拒绝。FAQ 写命令标记为受限命令，即便默认策略开放，也必须显式配置非空用户白名单。Jeppa 不推断平台管理员角色。

[permissions]
cooldown = 2

[permissions.commands.faq-set]
users = ["AUTHORIZED_OPERATOR_PERSON_ID"]

[permissions.commands.faq-delete]
users = ["AUTHORIZED_OPERATOR_PERSON_ID"]

[plugins.default]
enabled = true
areas = ["AUTHORIZED_INTERNAL_AREA_ID"]
channels = ["AUTHORIZED_INTERNAL_CHANNEL_ID"]

上述插件作用域是可选限制示例。删除 areas/channels 才是不限制；areas = [] 或 channels = [] 拒绝所有。只要存在插件域限制，私信就不可访问该插件。作用域与命令权限同时生效，帮助列表也遵循相同规则。

冷却按命令、会话、用户隔离，执行前预留；0 禁用，重启不保留。未知命令、权限拒绝与冷却命中静默处理，不追加刷屏回复。

05 / 多账号共享 Base，不共享身份

单账号使用导入器生成的 [oopz] 与 [bot].areas 即可。需要多账号时改为 [[accounts]]，每个账号分别声明标签、平台、订阅和认证。

[bot]
plugins = ["jeppa.plugins.default:setup"]

[[accounts]]
id = "service-a"
platform = "oopz"
areas = ["AUTHORIZED_INTERNAL_AREA_ID"]

[accounts.oopz]
method = "credentials"
device_id = "REPLACE_LOCALLY"
person_uid = "REPLACE_LOCALLY"
jwt_token = "REPLACE_LOCALLY"

这是结构示例，不能原样运行；只在本地编辑器填写凭据，按需重复账号表。多账号模式不能包含 [oopz] 或 [bot].areas（即便为空），也不能带任何 OOPZ_ 前缀环境变量，避免认证归属不明确。只支持 platform = "oopz"；重复登录到相同机器人身份会被拒绝。

同一进程并行运行账号连接；致命适配或插件错误会触发整体清理。账号标签是配置标识，数据隔离使用实际平台与登录后的机器人 ID，而非任意标签。QQ 尚未实现。

若数据库还有旧版未归属的 Oopz 数据，多账号必须在 [storage] 指定原账号标签：

[storage]
path = "data/jeppa.sqlite3"
legacy_account = "service-a"

legacy_account 必须匹配一个已配置账号的 id，不是人员 ID。单账号便利配置的账号标签固定为 main；只有一个账号时可省略归属项。先确认旧库确属该账号，不能为了启动而随意指定。

06 / 独立运行与固定脱敏日志

.\.venv\Scripts\python.exe -m jeppa start --config jeppa.local.toml
.\.venv\Scripts\python.exe -m jeppa status --config jeppa.local.toml
.\.venv\Scripts\python.exe -m jeppa logs --config jeppa.local.toml
.\.venv\Scripts\python.exe -m jeppa stop --config jeppa.local.toml

Linux / macOS 将解释器替换为 .venv/bin/python。start 脱离终端运行，保留启动目录；不要移动配置。run 也可由 stop 停止。同一数据库有本机文件锁，不能重复启动；停止使用回环控制通道等待清理，不向记录的 PID 直接发送 kill。

status 是本地进程状态，不等于账号已登录。logs 输出最近固定脱敏诊断；不记录命令参数、原始聊天、账号 ID、SDK 原始事件或异常正文。可信插件可以自行输出，不受此边界保证。

[storage]
path = "data/jeppa.sqlite3"

[logging]
path = "logs/jeppa.log"
max_bytes = 1048576
backups = 3

保护配置、数据库、日志和控制文件所在目录，仅允许运行账号访问。相对路径均以启动目录为准。这不是系统服务安装器，不提供开机自启或崩溃自动拉起；系统重启后需重新 start。

07 / 三种状态，不合成一个“在线”

  • 传输打开：WebSocket 已连接并发送鉴权，不代表服务器接受身份。
  • 鉴权确认：只在收到明确的 event=21、checkRes=true 后确认。没有确认帧，就保持未确认。
  • 已发送订阅：按 SDK 时序发出显式配置的域订阅，不等于服务器确认订阅，也不等于端到端消息成功。

重连会清空状态，并在通道打开后重新发送配置中的订阅。私信不需要域订阅。SDK 负责心跳与连接重试；Jeppa 不承诺离线重放、持久消息队列或恰好一次处理。公开监测报告不包含你的账号状态。

08 / 从 0.2.x 干净迁移

  1. 使用旧版本的 stop 停止实例，确认退出。离线备份真实配置与 SQLite 数据库及仍存在的配套日志文件；备份也需限制权限。
  2. 在原虚拟环境重新安装新源码或 Jeppa 仓库 Release wheel。
  3. 将旧入口 jeppa.plugins.utility:setup 替换为 jeppa.plugins.default:setup。没有兼容别名；旧的隐式内置命令也已移除。
  4. 自定义插件必须导出稳定 PLUGIN = PluginInfo(...)。使用新的公开 API，不要继续依赖 self_id、全局连接状态或运行时私有字段。
  5. 执行 check-config，再在授权账号中前台启动。schema v1 在打开存储时事务升级到 v2；旧 Oopz 数据在实际登录身份确定后才认领。多账号必须先明确 storage.legacy_account，不能由哪个账号先登录来抢占旧数据。

v2 命名空间包含稳定插件 ID、平台、机器人身份及会话范围。旧 utility FAQ 会在认领时迁到 default；目标已有同名键时整次认领失败，不覆盖数据。其他历史插件入口名不会自动改成新 ID，重命名须自行规划数据迁移。未知 schema 版本会被拒绝，不能用旧版本直接打开新库。

不要同时给两个账号认领同一份旧数据；先为原账号完成迁移，再扩展其他账号。存储是本地单进程 SQLite，只保存插件明确写入的 JSON，不自动保存聊天或凭据。
