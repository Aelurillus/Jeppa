01 / 从一个完整问候插件开始

在仓库根目录创建 examples/greet.py，或直接参考仓库中的可执行示例。插件模块必须导出 PLUGIN 和异步 setup。

from jeppa import Context, Plugin, PluginInfo

PLUGIN = PluginInfo(
    id="greet",
    name="问候",
    version="1.0.0",
    description="按名字打个招呼",
)


async def setup(plugin: Plugin) -> None:
    if plugin.config:
        raise ValueError("问候插件不接受配置项")

    async def greet(context: Context, args: tuple[str, ...]) -> None:
        if len(args) != 1:
            await context.reply("用法：/greet <名字>")
            return
        await context.reply(f"👋 你好，{args[0]}！")

    plugin.command("greet", greet, description="打个招呼：/greet <名字>")

PluginInfo 为冻结、带 slots 的数据类，字段为 id/name/version/description。ID 符合 [a-z][a-z0-9_-]*，在所有已加载插件中唯一；显示名称不是身份，入口路径也不再充当数据命名空间。

在本地配置中保留 default 并加入新入口，然后重启，发送 /greet Ada：

[bot]
plugins = ["jeppa.plugins.default:setup", "examples/greet.py:setup"]

文件路径相对于启动目录，也支持已安装模块的 my_plugin:setup。只有配置中声明的入口会加载，没有插件市场、自动发现或热重载。

02 / 加载与设置，以稳定 ID 关联

[plugins.greet]
enabled = true
areas = ["AUTHORIZED_INTERNAL_AREA_ID"]
channels = ["AUTHORIZED_INTERNAL_CHANNEL_ID"]

[plugins.ID] 只作用于 bot.plugins 声明的入口。省略 areas/channels 表示不限，空数组拒绝所有；域限制存在时，私信一律不可用。插件作用域与命令权限取交集，并共同过滤帮助列表。

运行时嵌入接口：

plugin = await runtime.load(
    "examples/greet.py:setup",
    settings={"greet": {"enabled": True}},
)

# 已有 setup 函数时，显式提供元数据：
plugin = await runtime.install(
    setup,
    info=PLUGIN,
    config={},
    areas=None,
    channels=None,
)

Runtime.load(entry, *, settings=None) 在导入模块后读取 PLUGIN.id，再选择设置。禁用入口返回 None，不执行 setup，但模块顶层代码仍会被导入。重复 ID 在 setup 之前拒绝。

plugin.info 提供元数据；plugin.config 是复制输入后的顶层只读映射，嵌套对象不是自动深冻结。插件应自行验证配置项和类型。示例 greet 与 default 均拒绝非空配置，不存在旧 name= 兼容参数或 utility 别名。

03 / 消息有平台，也有机器人身份

context.message 保留 text、area、channel、person、message_id、is_private 等消息字段，并要求非空的关键字身份字段 platform、bot_id。

  • 公开会话：(platform, bot_id, "channel", area, channel)。
  • 私信会话：(platform, bot_id, "private", channel, person)。
  • 自身消息由 message.person == message.bot_id 过滤，不使用全局 self_id。

await context.reply(text) 交给适配器回复原会话。Oopz 回复保留域、频道 / 私信对方以及消息引用；插件不需要拼装 SDK 的原始请求。

命令首个空白分隔词必须完整匹配，区分大小写。参数按空白拆分，不做 shell 引号或转义解析；/pingpong 不触发 /ping。未知命令静默，不自动翻译用户文本。

04 / 状态和帮助使用公开接口

Runtime 的只读查询与连接更新
接口含义
runtime.commands(message)返回当前消息可访问的 CommandInfo 元组，不消耗冷却。
runtime.plugins()返回 PluginInfo 元组，不暴露入口路径。
runtime.status(message)返回运行时长、插件、消息所属机器人连接状态、命令成功和失败次数。
runtime.set_connection(...)供适配器按平台、机器人身份更新连接事实，不是全局可写状态。
state = runtime.status(context.message)
# state keys:
# uptime, plugins, connection, command_successes, command_failures

runtime.set_connection(
    "oopz", bot_id,
    transport_open=True,
    auth_confirmed=False,
    subscription_sent=True,
)

CommandInfo 为冻结数据类，字段 name/description/plugin_id/restricted。未知身份的连接状态全部为 false。不要读取 _commands/_plugins/_started，也不要写旧的 runtime.connection。default 的帮助与状态同样依赖公开接口。

05 / 存储跟随插件 ID 和消息身份

store = plugin.store(context, scope="user")
count = store.get("visits", 0)
store.set("visits", count + 1)
entries = store.items()
store.delete("obsolete-key")

数据为 JSON 值，存储操作是同步本地调用。命名空间包含稳定插件 ID、平台、机器人身份及所选会话范围：

  • area：公开域内共享，私信禁止。
  • channel：公开域 + 频道；私信保留频道及对方。
  • user：公开域 + 频道 + 用户；私信保留频道及对方。

相同账号标签或相同显示域号不会合并数据。更改稳定 ID 仍会改变命名空间，不会自动移动所有历史插件数据。旧 utility FAQ 的特定迁移规则见版本迁移。

SQLite 仅记录插件明确写入的值；不是自动聊天记录、跨进程共享数据服务或安全沙箱。

06 / 获取资源后，立即登记清理

  • plugin.defer(close_callback) 接收同步或异步清理回调，卸载时逆序执行。
  • plugin.task(coroutine) 管理后台任务，关闭时取消并等待；未处理的后台异常是致命运行错误，不悄悄忽略。
  • setup 失败会撤销已注册命令和已登记资源；重复命令拒绝注册。
  • await plugin.close() 卸载插件并移除其命令。某项清理失败不跳过其余项，最终报告聚合错误。

在 setup 中创建资源，并在成功获取后立即登记清理；不要在模块顶层开启连接、文件或任务。导入副作用无法回滚。回复或插件异常会触发可见运行失败与清理，不无限重试同一条命令。

07 / 插件可信，不是插件安全沙箱

插件拥有进程的 Python 执行权限。可以访问文件、环境或网络，也可以绕过日志约束。配置隔离和命名空间隔离不限制恶意 Python 代码；加载前先审查来源与实现。

不要把账号 token 传给普通命令插件，不在输出中记录真实请求或消息正文。平台协议变化由适配器与兼容检查处理；QQ 仅是未来扩展方向，没有可用适配器。
