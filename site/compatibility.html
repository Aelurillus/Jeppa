实际支持范围监测什么报告如何读本地运行证据与限制反馈方式

01 / 支持范围：Oopz 文字接入

Jeppa 自研 Base，通过社区 Oopzbot-SDK 的 oopz-sdk 0.16.0 连接 Oopz。没有确认可使用的官方公共 Bot API；普通账号登录能力不意味着平台授予了 Bot 接入许可。

不要把架构扩展点当作已经交付的平台功能
项目当前边界
Oopz已实现文字适配；平台行为及账号授权仍需实际核对。
QQ / OneBot未实现。只有平台适配器扩展边界，没有可运行接入。
default现有全部文字命令归于同一插件，可整体关闭。
音频 / AI / WebUI不提供。
插件沙箱 / 消息重放不提供；可信 Python 执行与实时处理边界明确。

Oopz 用户服务协议对未授权第三方工具接入、登录与反向工程等有限制。使用前核对当前条款与书面授权；MIT 许可或社区 SDK 的开源许可不能替代平台授权。

02 / 每日监测公开变化

工作流计划在每日 02:23 UTC / 北京时间 10:23 运行，也可以手动触发。GitHub 定时任务可能排队或延迟，不是准点 SLA。

  • PyPI：读取 oopz-sdk 最新发布的公开元数据，不安装新发布代码。
  • SDK 仓库：读取默认分支 HEAD 引用，提示源代码变化。
  • 公开网页：读取 https://web.oopz.cn/ 入口及受限数量、体积和主机范围内的脚本资源，对资源路径与 SHA-256 指纹做比较。
  • 已安装 SDK 契约：离线执行适配边界测试，检查固定依赖版本与 Jeppa 的调用假设；不会为测试临时安装候选 SDK。

监测不使用账号、不登录、不访问认证接口、不抓聊天、不上传 token，也不执行远程脚本。检查输入来自公开资源；报告只保留固定标签和公开元数据。

03 / 三种结果，三种含义

以工作流 artifact 中的 JSON 与执行日志为准
报告状态含义退出码
unchanged成功取得的监测资源与已提交基线一致；不等于平台账号功能正常。0
changed公开资源相对基线有变化，需人工判断是否影响实际协议或 SDK。2
inconclusive网络、解析或资源获取失败，证据不足；不能当作“未变化”。1

出现变化或无法判断时，工作流维护一个带固定标记的议题，并附当前执行报告链接，避免每天创建重复 issue。适配契约测试失败仍会使任务失败，不会被“已发 issue”掩盖。

基线不会每天自动认可新结果，依赖也不会自动升级。维护者需查看差异、复核协议影响、验证改动，再显式提交新的基线。公开网页的无关样式更新可能触发变化，私有接口的变更也可能完全不改变这些公开资源。

04 / 在仓库本地运行相同监测

从仓库根目录执行。命令会访问上述公开网络资源；不要给它提供任何账号凭据。

python scripts/check_upstream.py --baseline scripts/upstream-baseline.json --output upstream-report.local.json

建议先在虚拟环境中执行，将 python 替换为安装指南中相应的完整解释器路径。JSON 包含 checked_at、status、changes、sources、failures 和 limitations。

维护者：什么时候更新基线？

先审阅当前报告与上游变化，按影响范围完成离线检查与经授权的实际验证。确认可以接受后，才使用脚本的 --update-baseline 参数，并将基线变更纳入代码审查。不能只为让检查变绿而接受未知失败。

参考监测脚本、已提交基线与工作流定义。

05 / 不同证据，不可相互替代

  • 离线回归通过：说明受测代码逻辑与固定 SDK 调用契约符合预期，不证明线上私有协议可用。
  • 公开资源未变：只说明这次监测对象与基线相同，不能排除服务端灰度、账号差异或不可见协议变化。
  • HTTP 200：只证明该请求取得 HTTP 响应，不证明消息确实出现或命令闭环成立。
  • 真实消息与回复：只证明已授权账号、目标域、当次行为；历史版本实测不代表当前所有命令都在线通过。
  • 鉴权确认帧：与连接打开、已发订阅分别记录；未见明确确认时不推断成功。

每日 Action 不是每日完整私有 API 验证。没有账号的公开监测不能证明账号安全、授权、消息可达或全部功能可用。这里没有伪造的绿色在线灯或最近检查时间。

06 / 反馈时只提供脱敏证据

功能或兼容问题请到仓库 Issues，提供 Jeppa / Python / SDK 版本、操作系统、固定错误类别、复现步骤及相关公开工作流链接。先核对凭据失败排查，不要为排障公开抓包。

不要上传请求头、JWT、密码、私钥、Cookie、真实配置、会话、原始 HAR、账号 ID 或聊天截图中的个人资料。凭据泄漏或漏洞请使用私下安全报告；泄漏后先撤销或轮换，不要只删除本地文件。
