01 / 先确认账号与接入边界

  • 仅操作自己已获授权的账号及目标域；先核对平台条款、域规则和账号权限。不获取他人会话，不把账号密码交给脚本。
  • 本地导入器只读取你明确选择的文件、显式标准输入或隐藏手动输入；不执行 cURL、不联网、不扫描浏览器资料、Cookie 数据库或历史记录。
  • 导入成功只说明本地解析与安全写入完成，不证明签名、账号身份、服务端授权或消息可达。
  • 本网站没有凭据表单、服务器接收逻辑、第三方分析或在线解析器。不要向聊天、issue、云端编辑器或任何网站粘贴原始请求。

不要执行复制出的 cURL 命令。它只作为本地解析输入。把它运行在终端，可能把秘密写入历史或重新发起请求。

02 / 在浏览器选一个已授权读取请求

  1. 在自己本机的浏览器登录 Oopz 网页客户端，进入确实获准访问的目标域。不要在公共设备、远程演示或录屏中操作。
  2. 按 F12 或 Ctrl+Shift+I，打开 Network / 网络。清空旧记录，关闭 Preserve log / 保留日志，只观察随后一小段操作；不要导出整个会话。
  3. 选择 Fetch/XHR，正常打开目标域频道或刷新已有列表。选一个正常读取信息的 GET 请求，不要发送消息、修改内容或试探未知接口。GET 只是筛选条件，不代表所有 GET 都没有副作用。
  4. 打开 Headers / 标头 → General / 常规，确认 Request Method 是 GET，Request URL 为 HTTPS，主机完全匹配下面列表之一，端口为默认 HTTPS 或 443。
gateway.oopz.cn
gateway1.oopz.cn
gateway2.oopz.cn
gateway-web1.oopz.cn

不接受相似拼写、额外子域后缀、HTTP、其他端口或带用户名密码的网址。网页入口 web.oopz.cn 本身不是凭据请求网关。

  1. 在 Request Headers / 请求标头 中，确认同一个请求完整包含 Oopz-Device-Id、Oopz-Person、Oopz-Signature。不完整时正常刷新后重新选择，不能从多个请求拼接补齐。
  2. 右键这一个请求，选择 Copy → Copy as cURL (bash)。不要选 PowerShell、Windows cmd、fetch、Node.js 或整组请求。即使你使用 Windows，也应选 bash 格式；后续只是保存文本，不运行 shell。

如果新版客户端已不再发这些字段，停止导入并查看兼容性维护说明。不要猜测字段或加入未经核实的密钥。

03 / 三个请求头与内部域 ID

只取同一次已授权 GET 请求中的三个值，名称大小写不敏感
请求头本地 TOML 字段含义
Oopz-Device-Id[oopz].device_id该会话设备标识，不随机生成。
Oopz-Person[oopz].person_uid登录者内部人员 ID，不是昵称、手机号或展示编号。
Oopz-Signature[oopz].jwt_token会话令牌，按密码保护；不添加 Bearer 前缀，不自行改写。

Oopz-Sign、Oopz-Time 不是会话令牌，不要放进 jwt_token。不需要额外私钥。导入器不保存 Cookie、Authorization、其他标头、请求体、网址或查询参数。

如何核对 --area

这里要的是 SDK 订阅使用的内部域 ID，不是显示域号、域名、邀请链接、频道 ID 或人员 ID。在该目标域的已授权读请求中查看 Payload → Query String Parameters 是否有明确的 area；若接口返回域对象，可在 Preview 核对对应对象的内部 area 字段。确认与当前目标域对应后逐字使用。

若只能看到显示编号，或无法确认字段关系，先不填写域，不上传整段响应求助，也不猜 UUID。导入器不从 URL、HAR 或响应自动推断域。每个授权域显式传一次 --area；省略即 areas = []，仅私信，不订阅全部域。

04 / 先限制目录权限，再保存临时文本

使用 *.local.* 名称，保存在本机私有目录，不放网盘、共享目录或公共桌面。Git 忽略规则不是访问控制；关闭第三方剪贴板记录和跨设备同步。下面准备命令不含凭据，可以复制。

Windows PowerShell

$privateDir = Join-Path $env:LOCALAPPDATA 'Jeppa-private'
New-Item -ItemType Directory -Path $privateDir -ErrorAction Stop | Out-Null
$sid = [System.Security.Principal.WindowsIdentity]::GetCurrent().User.Value
icacls $privateDir /inheritance:r /grant:r "*${sid}:(OI)(CI)F" | Out-Null
if ($LASTEXITCODE -ne 0) {
    Remove-Item -LiteralPath $privateDir -ErrorAction Stop
    throw '无法限制目录权限，已停止；不要保存凭据。'
}
notepad (Join-Path $privateDir 'request.local.txt')

这是专用新目录示例。已存在时应停止并换一个新目录名，不要删除现有配置来“重试”，不要在未检查的既有目录反复套用 ACL 命令。在记事本粘贴单条 cURL 并按 UTF-8 保存，关闭编辑器。事先关闭标签恢复，并在操作后删除含秘密的恢复副本；不要把内容当 PowerShell 命令运行。

Windows 输出由导入器设置受保护 DACL，仅允许当前用户 SID 完全访问；不是依赖 Windows 上不足以保护文件的 chmod 600。权限设置失败时不继续写入凭据；提示清理失败时，只在本机检查残留文件，不分享内容。管理员、同用户恶意进程和已入侵系统不在此保护边界内。

Linux / macOS

在非共享本地目录先运行 umask 077，用无云端插件的本地编辑器新建 request.local.txt，粘贴保存后执行 chmod 600 request.local.txt。导入器新输出文件使用 0600 权限。

05 / 在已安装 Jeppa 的环境中导入

先完成安装，再使用同一虚拟环境解释器。以下通用命令中的 python 是该环境的 Python；Windows 在仓库根目录可写为 .\.venv\Scripts\python.exe，Linux / macOS 为 .venv/bin/python。

python -m jeppa.credentials --input request.local.txt --area INTERNAL --output jeppa.local.toml

上面假设当前目录已受限且含输入文件，INTERNAL 必须替换。若按 Windows 私有目录示例保存，请在仓库根目录执行：

.\.venv\Scripts\python.exe -m jeppa.credentials --input "$privateDir\request.local.txt" --area INTERNAL --output "$privateDir\jeppa.local.toml"
.\.venv\Scripts\python.exe -m jeppa check-config --config "$privateDir\jeppa.local.toml"

Linux / macOS 可同样使用输入与输出的绝对路径。多个域重复 --area，仅私信则完全省略该参数。

导入器参数与失败边界
参数行为
--input PATH仅读取明确指定的 UTF-8 文件，最大 2 MiB。
--stdin显式启用才读标准输入，同样最多 2 MiB。终端粘贴可能回显，优先使用文件；不用含凭据的 echo 或 here-string。
--manual隐藏交互输入；未指定输入方式时也使用此模式。
--output PATH默认 jeppa.local.toml；只新建，不覆盖文件、目录或符号链接，没有 --force。
--area INTERNAL仅接受明确填写的域 ID，可重复，重复值去重，不扩大或推断订阅。

主 CLI 也提供同参数的 jeppa import-session。导入本身不联网；随后 check-config 仍只是本地检查。真正运行会连接平台，见首次启动。更新令牌先写另一个新的受限 *.local.toml，停止旧进程后再明确替换，不覆盖运行中的配置。

06 / 其他输入：明确 JSON 或既有本地 HAR

明确导出的请求头 JSON 结构

仅从同一个已授权 GET 请求制作，所有值为字符串。示例只是格式，不可直接登录：

{
  "url": "https://gateway.oopz.cn/REPLACE_WITH_SELECTED_GET_PATH",
  "method": "GET",
  "headers": {
    "Oopz-Device-Id": "REPLACE_LOCALLY",
    "Oopz-Person": "REPLACE_LOCALLY",
    "Oopz-Signature": "REPLACE_LOCALLY"
  }
}

headers 也可为 HAR 风格的 name/value 数组。缺 URL 的片段、单独的请求头对象、重复 JSON 字段或重复凭据头会被拒绝。不拼接不同设备或账号的请求。

为什么不建议导出 HAR？已有 HAR 能否读取？

优先复制单个 cURL。HAR 常含多个账号 token、Cookie、请求体、响应和他人资料。仅在你已有自己明确授权保管的本地 HAR、且能承担敏感性时，使用同一 --input 本地读取；不上传到网站或在线转换工具。

只检查 log.entries[].request 的网址、方法和标头，不使用响应。无目标头的记录不参与；含任意目标凭据头的记录必须来自批准网关 GET 且三项完整。多条记录必须完全相同；不同账号 / 设备 / token、跨域夹带、部分字段、重复头或超过 2 MiB 都拒绝，不挑“最新一条”。失败就重新复制单个请求，不靠裁剪大量捕获猜测。

cURL 格式不支持怎么办？

只接受一条 curl、一个批准 HTTPS 地址、请求头及少量复制选项。Cookie、User-Agent、Referer 被丢弃；请求体、脚本、多命令、重定向、配置文件选项及不支持的 shell 语法会拒绝。bash ANSI-C 引号 $'…' 和 PowerShell / cmd 格式不保证兼容，请改用明确 JSON 或隐藏手动输入。命令替换不会执行，但也不应把脚本表达式当作凭据。

07 / 隐藏输入，或完全手工编辑

推荐：隐藏交互输入

python -m jeppa.credentials --manual --area INTERNAL --output jeppa.local.toml

依次输入同一次授权 GET 请求的完整 HTTPS 地址、Oopz-Device-Id、Oopz-Person、Oopz-Signature。四项均由 getpass 隐藏；地址仅用于网关校验，不写入配置。不输入头名称、包围引号或自行生成的值。无法隐藏输入时工具会停止，不退回明文；改用本地交互终端。

完全手工编辑 TOML

先创建受限空文件再填写秘密，不要写完才设置权限。Windows 可在前述新私有目录中执行：

$config = Join-Path $privateDir 'manual.local.toml'
New-Item -ItemType File -Path $config -ErrorAction Stop | Out-Null
icacls $config /inheritance:r /grant:r "*${sid}:F" | Out-Null
if ($LASTEXITCODE -ne 0) {
    Remove-Item -LiteralPath $config -ErrorAction Stop
    throw '无法限制文件权限，已停止；不要填写凭据。'
}
notepad $config

Linux / macOS 先 umask 077，用本地编辑器新建 manual.local.toml，核对权限 0600。仅在本机填写下面的结构，所有 REPLACE 值都必须替换：

[oopz]
method = "credentials"
device_id = "REPLACE_WITH_OOPZ_DEVICE_ID"
person_uid = "REPLACE_WITH_OOPZ_PERSON"
jwt_token = "REPLACE_WITH_OOPZ_SIGNATURE"

[bot]
areas = ["REPLACE_WITH_INTERNAL_AREA_ID"]
plugins = ["jeppa.plugins.default:setup"]

仅私信把 areas 改为 []。双引号与反斜线须遵守 TOML 转义；不确定时使用导入器。该文件只配置单账号，不从 HAR 自动创建多账号。default 是全部现有基础命令的整体插件。

08 / 保存后清理，不把删除当撤销

  1. 在本机核对输出存在和权限；不用 cat/type 回显整份配置，不截图。使用 check-config 检查结构即可。
  2. 删除自己明确创建的临时请求文本、HAR 临时副本与编辑器恢复副本。Windows 可用 Remove-Item -LiteralPath (Join-Path $privateDir 'request.local.txt')；Linux / macOS 可用 rm -- request.local.txt。不递归、不用通配符清空凭据目录。
  3. PowerShell 执行 Set-Clipboard -Value ''，再通过 Win+V 清除历史并关闭跨设备同步。macOS 可用 printf '' | pbcopy；Linux 使用桌面剪贴板管理器清理内容与历史。清空 DevTools 记录，关闭敏感编辑器标签并处理备份。
  4. 最终配置只保存在本机受限目录。停用时停止相应进程，处理配置与自己的备份。普通删除不保证 SSD、备份或同步副本安全擦除。

删文件或清剪贴板不会使服务端会话失效。疑似泄漏时先用平台客户端的会话 / 设备管理、退出登录等方式撤销，无法确定范围就联系平台。不要仅修改本地值后认为旧 token 已失效。

09 / 失败与令牌到期，按原因停止处理

输入被拒绝 / 缺字段 / 多组凭据

重新选择一个当前、完整、已授权的网关 GET 请求。确认 Copy as cURL (bash)、三个字段来自同一请求、HTTPS 主机精确匹配，不混入 body、脚本、多个账号或不同设备。不要上传原文求助；不支持的 cURL 格式可改为 JSON 或隐藏输入。

文件已存在 / 权限失败 / 无法隐藏输入

不强行覆写、不跳过 ACL。换一个新的受限输出文件，确认目录为自己可访问的本地位置。若工具提示残留清理失败，在本机处理指定文件。隐藏输入失败则换本地交互终端，不用明文参数传 token。

JWT 已过期 / 导入成功但无法登录

只有三段 JWT 且载荷含可读数值 exp 时才做本地到期检查，已过期会拒绝；不验证签名，不代表未过期令牌有效。没有 exp 仍可能被服务端拒绝，系统时钟也会影响本地判断。

停止机器人，回到自己客户端核对账号和授权，重新取得当前 GET 请求，生成新配置并明确替换旧配置。不循环尝试旧令牌、不添加私钥、不改用来历不明的请求。

错误只显示固定中文类别，不输出原始地址、凭据或异常正文。反馈只提供工具版本、输入类型和脱敏错误类别；不附请求、配置、token、Cookie、HAR、私钥或截图。泄漏与漏洞使用私下安全报告。
